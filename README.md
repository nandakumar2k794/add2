# 🍕 Beginner's Guide: In-Memory Food Ordering System in Spring Boot

Welcome to your first hands-on activity in Spring Boot! This guide is designed specifically for beginners. 

In this activity, you will build a simple **Food Ordering REST API** that allows you to:
1. **Add new food items** (using a `POST` request)
2. **View all available food items** (using a `GET` request)

We will do this **without any database** by storing food items in memory (using Java's built-in `List`).

---

## 🏛️ Spring Boot Architecture: The 4 Layers

In Spring Boot, code is organized into separate layers so that each layer does only one job.

```
       [ Client / Browser / Postman ]
                     │  HTTP Request (GET / POST)
                     ▼
  ┌─────────────────────────────────────┐
  │         1. CONTROLLER LAYER         │  Receives HTTP request, extracts data,
  │         (@RestController)           │  and returns HTTP response.
  └──────────────────┬──────────────────┘
                     │  Calls method
                     ▼
  ┌─────────────────────────────────────┐
  │          2. SERVICE LAYER           │  Contains business logic, calculations,
  │              (@Service)             │  and validations.
  └──────────────────┬──────────────────┘
                     │  Calls method
                     ▼
  ┌─────────────────────────────────────┐
  │        3. REPOSITORY LAYER          │  Handles data storage/retrieval.
  │            (@Repository)            │  (In our case: an In-Memory List).
  └──────────────────┬──────────────────┘
                     │  Uses
                     ▼
  ┌─────────────────────────────────────┐
  │           4. MODEL LAYER            │  Plain Java Object representing the
  │              (POJO)                 │  data structure (id, name, price).
  └─────────────────────────────────────┘
```

## 📁 Required Folder & Package Structure

Navigate to `src/main/java/com/example/App/` inside your project. Make sure your package folders match this structure:

```
com.example.App/
 ├── AppApplication.java        (Main class generated by Spring Boot)
 ├── model/
 │    └── Food.java             (Defines what a "Food" looks like)
 ├── repository/
 │    └── FoodRepository.java   (Stores the list of foods in memory)
 ├── service/
 │    └── FoodService.java      (Applies business rules before saving/fetching)
 └── controller/
      └── FoodController.java   (Handles incoming HTTP GET and POST requests)
```

## 💻 Step-by-Step Code Implementation

### Step 1: Model Layer (`model/Food.java`)
The Model is a standard Java class (POJO - Plain Old Java Object). It defines the fields of a food item.

```java
package com.example.App.model;

public class Food {
    private Long id;
    private String name;
    private double price;

    // 1. Default No-Argument Constructor (Required by Spring to convert JSON to Java)
    public Food() {
    }

    // 2. Parameterized Constructor
    public Food(Long id, String name, double price) {
        this.id = id;
        this.name = name;
        this.price = price;
    }

    // 3. Getters and Setters (Required so Spring can read and write the fields)
    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public double getPrice() {
        return price;
    }

    public void setPrice(double price) {
        this.price = price;
    }
}
```

---

### Step 2: Repository Layer (`repository/FoodRepository.java`)
The Repository manages the data storage. Since we aren't using a database, we use a `List<Food>` stored in memory.

```java
package com.example.App.repository;

import com.example.App.model.Food;
import org.springframework.stereotype.Repository;

import java.util.ArrayList;
import java.util.List;

@Repository // Marks this class as a Spring Bean for data access
public class FoodRepository {

    // In-memory list simulating a database table
    private final List<Food> foodList = new ArrayList<>();

    // Save a new food item into the list
    public Food save(Food food) {
        foodList.add(food);
        return food;
    }

    // Return all food items currently in memory
    public List<Food> findAll() {
        return foodList;
    }
}
```

---

### Step 3: Service Layer (`service/FoodService.java`)
The Service layer sits between the Controller and the Repository. It handles business logic, checks, and orchestrates actions.

```java
package com.example.App.service;

import com.example.App.model.Food;
import com.example.App.repository.FoodRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

import java.util.List;

@Service // Marks this class as a Spring Bean containing business logic
public class FoodService {

    private final FoodRepository foodRepository;

    // Constructor Injection: Spring automatically provides FoodRepository here
    @Autowired
    public FoodService(FoodRepository foodRepository) {
        this.foodRepository = foodRepository;
    }

    // Business method to add a food item
    public Food addFood(Food food) {
        // Here you can add business validation (e.g. price must be > 0)
        return foodRepository.save(food);
    }

    // Business method to get all food items
    public List<Food> getAllFoods() {
        return foodRepository.findAll();
    }
}
```

---

### Step 4: Controller Layer (`controller/FoodController.java`)
The Controller handles HTTP requests, maps URLs, and formats responses as JSON.

```java
package com.example.App.controller;

import com.example.App.model.Food;
import com.example.App.service.FoodService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController // Tells Spring this class responds to HTTP requests with JSON data
@RequestMapping("/api/foods") // Base URL for all endpoints in this controller
public class FoodController {

    private final FoodService foodService;

    // Constructor Injection: Spring injects the FoodService instance
    @Autowired
    public FoodController(FoodService foodService) {
        this.foodService = foodService;
    }

    // 1. POST Endpoint: Add a new food item
    // URL: POST http://localhost:8080/api/foods
    @PostMapping
    public Food addFoodItem(@RequestBody Food food) {
        // @RequestBody converts the incoming JSON from the request into a Food Java object
        return foodService.addFood(food);
    }

    // 2. GET Endpoint: Retrieve all food items
    // URL: GET http://localhost:8080/api/foods
    @GetMapping
    public List<Food> getAllFoodItems() {
        return foodService.getAllFoods();
    }
}
```

## 🧪 How to Test Your API

### 1. Run your Spring Boot Application
Run the project using your IDE's Run button or using the terminal:
```bash
mvn spring-boot:run
```

### 2. Test the GET Endpoint (Retrieve items)
Open your web browser or run this curl command in your terminal:
```bash
curl http://localhost:8080/api/foods
```
*Expected output (initially empty):*
```json
[]
```

### 3. Test the POST Endpoint (Add an item)
Use `curl` or Postman to send a POST request with a JSON payload:

**Using PowerShell:**
```powershell
Invoke-RestMethod -Uri "http://localhost:8080/api/foods" -Method Post -ContentType "application/json" -Body '{"id": 1, "name": "Margherita Pizza", "price": 9.99}'
```

**Using Git Bash / CMD / Linux curl:**
```bash
curl -X POST http://localhost:8080/api/foods \
  -H "Content-Type: application/json" \
  -d "{\"id\": 1, \"name\": \"Margherita Pizza\", \"price\": 9.99}"
```

### 4. Verify by Calling GET Again
Visit `http://localhost:8080/api/foods` in your browser. You will now see:
```json
[
  {
    "id": 1,
    "name": "Margherita Pizza",
    "price": 9.99
  }
]
```

## 💡 What Beginners Mostly Misunderstand in Spring Boot

Here are the most common pitfalls and misconceptions beginner developers face:

### 1. "Why have both a Service and a Repository if the Service just calls the Repository?"
* **The Misunderstanding**: Many beginners think the Service layer is useless boilerplate when it only has one line calling the repository.
* **The Reality**: 
  - The **Repository** only knows how to store and fetch raw data.
  - The **Service** holds business rules (e.g., *"Is the user logged in?"*, *"Is the food price positive?"*, *"Send an email confirmation after adding the food"*).
  - Keeping them separate ensures you don't clutter your data storage code with business logic, making testing and updating clean and simple.

---

### 2. The `new` keyword vs. Dependency Injection (`@Autowired`)
* **The Misunderstanding**: Writing `FoodService service = new FoodService(...)` inside the controller.
* **The Reality**: 
  - Spring is an **IoC (Inversion of Control)** container. You should **never manually create** service or repository instances using `new`.
  - Annotate classes with `@Service` or `@Repository`, and Spring will automatically instantiate them and supply them via `@Autowired` (called **Dependency Injection**).

---

### 3. Where to put packages (Component Scanning)
* **The Misunderstanding**: Creating packages outside the root package (e.g., putting `controller` in `com.mycompany.controller` while `AppApplication` is in `com.example.App`).
* **The Reality**: 
  - By default, `@SpringBootApplication` only scans classes in its own package and **sub-packages** (`com.example.App.*`).
  - If you put your controller or service outside `com.example.App`, Spring will never detect them, and your endpoints will return **404 Not Found**.

---

### 4. In-Memory Data Disappears on Restart
* **The Misunderstanding**: "I added 5 food items, but when I restarted the server, all my data is gone!"
* **The Reality**: 
  - An `ArrayList` only exists in your computer's RAM while the Java application process is running.
  - When the application stops, RAM is cleared. Later in your learning journey, you will use persistent databases like MySQL, PostgreSQL, or H2 using Spring Data JPA.

---

### 5. Missing `@RequestBody` in `@PostMapping`
* **The Misunderstanding**: Writing `public Food addFoodItem(Food food)` without `@RequestBody`.
* **The Reality**: 
  - Without `@RequestBody`, Spring will look for query parameters or form fields in the URL instead of the JSON payload.
  - As a result, all fields inside your `Food` object will be `null` or `0.0`.
  - Always remember `@RequestBody` when receiving JSON from client requests!

---

### 6. `@RestController` vs `@Controller`
* **The Misunderstanding**: Using `@Controller` instead of `@RestController`.
* **The Reality**: 
  - `@Controller` is meant for traditional web applications that return HTML views (like Thymeleaf templates). If you return an object, Spring looks for an HTML file with that name and throws a `404` or error.
  - `@RestController` combines `@Controller` and `@ResponseBody`. It automatically converts Java objects into JSON strings returned directly in the HTTP response.

---

### 7. Empty Default Constructor in Model
* **The Misunderstanding**: Providing a constructor with arguments `Food(Long id, String name, double price)` without also providing a blank constructor `Food()`.
* **The Reality**: 
  - Spring uses libraries like Jackson to deserialize JSON into Java objects.
  - Jackson requires a no-argument constructor `public Food() {}` to instantiate the object before setting values via setters. If it's missing, you may see Jackson or deserialization errors.
